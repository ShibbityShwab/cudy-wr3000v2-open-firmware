# 07 - Upstream DTS bindings cleanup

This note records the cleanup that turned the lab board DTS into a
submission-oriented board devicetree, every node/property removed or renamed,
where the retained measured facts live, and the items that still block an
upstream submission.  The DTS itself is now free of TODO/experiment prose:
those notes live here.

- single source: `target-skeleton/dts/luofu-r116.dts` (replaced in place;
  before the cleanup it was 1,329 lines, after it is 712 lines);
- upstream artefact: `dts-series/0001-arm-dts-hisilicon-luofu-r116-loader-handoff.patch`
  (DTS-0001), regenerated byte-identically from the single source (sha256
  `d8afee63447d6205566e935fd8ec1beeb103e1eada43a67f9f5a129558df59f6`; 725
  lines);
- bench image: unchanged source of truth; the image build runs
  `Build/luofu-pad-dtb` because the cleaned DTS compiles to an unaligned
  DTB totalsize (see section 5);
- this note is also the home of the removed provider/bench commentary; the
  full pre-cleanup text remains in git history (submodule commit before this
  cleanup) and in the older design docs referenced below.

## 1. Scope of the cleanup

Kept, because they are measured board facts and the submission needs them:
the stock-loader hand-off contract (`/aliases/console` and
`/reserved-memory/flashinfo@80600000`), the SMP `enable-method`, the
CPU/clock/GIC/SCU/TWD/L2 nodes, the UART console, both GPIO controllers, the
stock board_id=3 buttons/LEDs, the MDIO bus and four PHYs, the five GMACs (gmac0
disabled; gmac1..4 are the four wired ports behind LSW ports 9..12), the FMC
SPI-NAND controller and the verbatim stock partition map, the LSW register
windows/ports, the PIE ring configuration, the boot-selector, reboot and
watchdog nodes, and the i2c/PCIe nodes marked disabled.

Removed or deferred: experiment/bench prose, TODO markers, unverified or
driver-less vendor blocks (SP804, WOE engine, thermal sensor/zone, Wi-Fi PCIe
endpoints), redundant enabled properties, and one unused UART alias.  No
measured register/interrupt/clock/partition value was changed; the property
multiset comparison between the old and the cleaned DTB shows only the
intentional removals below.

## 4. Binding consistency review

The DTS was checked against the YAML bindings that the kernel series adds and
against the standard bindings already in the 6.18 tree (required properties,
reg/reg-names order and counts, clock/reset name lists, interrupt names, node
names/unit addresses).  The in-series binding files were read from a tree with
all 51 release patches applied.

Deviations and findings that a reviewer will still see:

1. `flashinfo@80600000` uses the vendor compatible
   `"hsan,flashinfo_reserved"`.  It is the stock loader contract and must
   not be renamed, but there is no upstream binding for it.  This needs either
   an accepted binding for the loader hand-off window or a different
   upstream-accepted hand-off mechanism.
2. The bdinfo MAC source uses `fixed-layout` + `mac-base` nvmem cells.
   Those are v6.19 bindings; the 6.18 tree has no schema for them.  The
   measured bdinfo offset (0xde00) and the two GEMAC consumers are retained,
   but a 6.18 submission needs a backport policy or must wait for 6.19.
3. The switch binding puts the two DDR regions first in `reg-names`, so the
   node unit address is the queue DDR base (`ethernet-switch@80000000`).
   The DTS matches the binding, but for upstream the binding should be
   reordered (MMIO windows first, DDR regions last) and the node renamed with
   it.
4. The TWD timer interrupt is kept as the measured vendor encoding
   (PPI 13, `0x301` = CPU mask 2 + edge rising).  Standard TWD timer
   wiring is usually level-high (`0x304`); confirm on hardware before
   submission.
5. The board compatible order (cudy last, note in section 3) must be fixed
   together with `target/linux/hisilicon` board_name/sysupgrade metadata
   (outside this cleanup's scope).
6. The draft in-series bindings and drivers (CRG, watchdog, FMC, MDIO, GMAC,
   PIE, LSW, pinctrl, PCIe, reboot, boot-selector) are not upstream, so the
   board DTS cannot be submitted before they are accepted.

## 5. Compile/PAD facts and validation commands

- The cleaned DTS compiles with cpp + dtc to a **11,702-byte** DTB, sha256
  `160fad93e0d0556b8959a87efa8b5f05623e7488b632341f871d4e7a520c21b8`.
  The totalsize (11,702) is **not** 8-byte aligned; the image build's
  `Build/luofu-pad-dtb` step pads it to **11,704 bytes** (sha256
  `de2ccd5f678a69e1b925567cbd5c44900c567b679bef965f53faa3e00c2aa84f`) and
  folds the padding into the FDT totalsize; the loader hand-off contract
  survives the pad.  This is the same measured failure mode documented in
  `../../docs/TRAILER-FORMAT.md` section 11: an unaligned totalsize made
  the stock bootfip gate-word load data-abort and fall back to stock.
- The DTS is compiled for review with the patched kernel tree's headers:
  `cpp -nostdinc -I include -I arch/arm/boot/dts -undef -D__DTS__ -x assembler-with-cpp`
  followed by `dtc -I dts -O dtb`; both returned RC=0 with 0 diagnostics,
  and the extra warning set `unit_address_vs_reg simple_bus_reg
  avoid_unnecessary_addr_size unique_unit_address_if_enabled` produced no
  warnings on the cleaned file.
- There is **no dtschema/dt-validate/yamllint tooling available** in this
  checkout or in the provisioned environment (no `dtschema` module, no
  `dt-validate` binary, no pip/yamllint), so a real `make dtbs_check` /
  `dt_binding_check` pass could not be run.  The binding review above is a
  manual required-property/name check against the in-tree YAMLs; a full
  dt-schema pass remains part of the submission blocker set.
- The release-line validator `tools/check-release-line.sh` applies DTS-0001
  to the release-line tree, compiles it, checks the loader contract, verifies
  byte-identity with this single source and exercises the pad step; its result
  is recorded in `05-release-line.md` section 9 and `04-validation.md`.

## 6. What is still missing for an upstream submission

1. The kernel (drivers + YAML bindings + machine) is still a draft series:
   26 review-form patches plus the DTS companion, not an accepted upstream
   submission.  The DTS references that series' compatibles.
2. `hsan,flashinfo_reserved` has no upstream binding (see section 4).
3. `fixed-layout`/`mac-base` nvmem cells are v6.19 content on a 6.18
   baseline.
4. The switch binding/node naming needs the MMIO-first cleanup.
5. The cudy board compatible ordering + OpenWrt board metadata sync.
6. TWD timer interrupt flags need a hardware re-check.
7. The board DTS is still missing upstream-required content that is out of
   this cleanup's scope: pinctrl consumer states, MBus/clock consumers for
   every enabled node, a complete PCIe description (RCs are disabled), the
   A/B boot-selector protocol (only the measured 0x10/0x11 cell is modelled),
   and the LED function/color descriptions (labels are vendor strings).
8. Wi-Fi, thermal and the unused vendor blocks remain out of scope; this is a
   wired-first board DTS.

## 7. Single-source and regeneration

The only supported source is `target-skeleton/dts/luofu-r116.dts`.  After
any change, regenerate DTS-0001 and the recorded hashes with:

    python3 tools/gen-dts-series-patch.py \
        --pristine <extracted linux-6.18.60> \
        --target-dts ../../target-skeleton/dts/luofu-r116.dts \
        --out dts-series/0001-arm-dts-hisilicon-luofu-r116-loader-handoff.patch

then run `tools/check-release-line.sh --use-tree <pristine> <workdir>` and
refresh `validation/sha256sums.txt`.  The DTS-0001 patch must be
byte-identical to the single source; the validator fails otherwise.

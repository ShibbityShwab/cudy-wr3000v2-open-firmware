## 2. Loader hand-off contract carried by the DTS (release-critical)

Two nodes are consumed by the stock U-Boot `bootfip` staging before the kernel
runs; without them the staging aborts and CPU1 never enters the pen-poll loop
(the 2026-11-21 SMP root cause; `docs/SMP-RE.md` section 24):

```dts
aliases {
    serial0 = &uart1;
    serial1 = &uart0;
    console = &uart1;            /* vendor base DTB contract; bootfip staging */
};

reserved-memory {
    #address-cells = <1>;
    #size-cells = <1>;
    ranges;

    flashinfo@80600000 {
        compatible = "hisilicon,luofu-flashinfo", "hsan,flashinfo_reserved";
        reg = <0x80600000 0x4000>;
        atag-offset = <0x1000>;
    };
};
```

Verified in the decompiled DTB produced from the entry:
`console = "/serial@1010f000"`, `serial0`/`serial1` aliases present,
`compatible = "hisilicon,luofu-flashinfo", "hsan,flashinfo_reserved"`,
`reg = <0x80600000 0x4000>`, `atag-offset = <0x1000>`, and
`/cpus enable-method = "hisilicon,luofu-smp"`.

## 5. Remaining: the `reset-gpios` fold (the one open v2 content decision)

The hardware-validated boot line uses the committed **separate** patch
`013a-arm-pci-luofu-endpoint-reset-pulse.patch`: at RC0 probe the DWC glue
drives SoC GPIO0 pins 20/21/28 LOW (assert) for 20 ms then HIGH (release) for
100 ms, before the RC clock and LTSSM start.  The upstream form wants those
board lines as **DT data**, so the planned v2 folds `013a` into patch 0013 as
a `reset-gpios` property (+ binding schema) and adds the property to this
board DTS.  That is an **active-DTS** change and needs one attended boot on the
unit (2 CPUs, both PCIe endpoints, NAND/UBI, serial), plus a rebuild of the L2
form and a DTS-0001 regeneration.  Design sketch:

* board DTS: `reset-gpios = <&gpio0 20 GPIO_ACTIVE_LOW>, <&gpio0 21 GPIO_ACTIVE_LOW>, <&gpio0 28 GPIO_ACTIVE_LOW>;`
  on the PCIe RC0 node (or a board-level reset-controller child);
* binding: document the property (open drain? bounded pulse? no hog);
* driver: `devm_gpiod_get_array()`, same assert/release timing, keep the
  "pulse before clock/LTSSM" ordering, fail closed if the property is absent on
  this board, no other behaviour change;
* keep the bench gate out of the submission (DT state only);
* regenerate DTS-0001 + L2, re-run both validators, then the one attended boot.

Until that happens, DTS-0001 v3 is correct for the **current** booted line and
must **not** be posted as part of a v2 form (v1/v3 are host-only drafts; the
cover letter wording for the current state is in
`../wifi-upstream-final/UPSTREAM-SERIES-FINAL.md`).

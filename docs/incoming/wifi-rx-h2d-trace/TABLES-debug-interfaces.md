## T5. `save_hostmem` - the one useful debug-module facility for H2D (decoded [V])

Function `oal_pcie_debug_save_hostmem` at `.text+0xf04`:

1. `sscanf_s(arg, format, &addr, &len, &path)` must return 3 (format string = the `save_hostmem`
   usage line printed by `echo help`);
2. resolves the default PCIe handler and **`ioremap(addr, len rounded up to 4)`** - it does **not**
   call the device `devca_to_hostva` transform, so `addr` is a **host physical address** (this is
   the "hostmem" in the name);
3. allocates a `vmalloc(len)` bounce buffer, `filp_open(path, O_WRONLY|O_CREAT, 0666)`;
4. copies the mapped region 4 bytes at a time with `dsb sy` / `dsb st` / `arm_heavy_mb` barriers;
5. logs `save_hostmem cpu:0x%lx len:%u save_path:%s done`.

Grammar (full sysfs write): `echo 'save_hostmem 0 0x<host-phys> <decimal-len> <path>' > /sys/hisys/plat/pcie`
(the `0` is the dispatcher's chip id; the handler then parses `0x<phys> <len> <path>`).
Uses: dump the SR node array (size 8*depth at the `+0x10` base) and a window of message buffers
when `/dev/mem` is unavailable. Writes only the output file under the stock overlay.

## T6. `plat_debug.ko` - same family, platform-only dependency (decoded [V])

Carries its own copies of the `oal_pcie_debug_*` command dispatcher and the `hcc_test_*` facility
(and `oal_pcie_print_debug_usage`, `oal_plat_test_print_debug_usage`, `device_oam_log_switch_send_proc`),
depends on `hi5622v100_plat` only; also imports `bal_*`/`pcie_*`/`oam_log_*` and a `power:bool`
module parameter. Because the surfaces are the same as `wifi_debug.ko`'s, load only one - prefer
`wifi_debug.ko` on the full vendor stack (phase-7's successful load) and treat the -ENOMEM group
failure as the duplicate/collision symptom, not a new capability.

## T7. What the debug modules do NOT provide (the negative that matters)

* **no H2D message log / ring dump**: the only queue-dump export `hcc_queue_info_dump` is a no-op
  stub in this build (`hi5622v100_plat.ko .text+0x124a8: mov r0,#0; bx lr`) [V];
* no trace/debugfs file for posted messages; the base `/sys/hisys/plat/debug` is a logging stub;
* `hcc_test` is a traffic generator, not a capture;
* nothing records the HCC frame bytes (those stay in host DRAM and are read by M1/M3).

**Therefore: H2D trace = M1 (SR-ring sampler, no module) / M2 (kprobes, no module); M3
(`save_hostmem`) is the debug-module-assisted bulk-snapshot fallback.**

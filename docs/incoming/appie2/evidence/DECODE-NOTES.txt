appie2 decode notes - anchors used (host-only, local gitignored disassembly)

Inputs (local, gitignored, never committed): wifi.dis.txt / wifi.nm.txt, produced from the
vendor driver hi5622v100_wifi.ko in the local recovery extract. Only link-time addresses,
symbol names and decoded field layouts are quoted here - no vendor bytes.

Tooling used to re-derive the anchors:
  grep -n '<symbol>' wifi.nm.txt                    # symbol -> section-relative address
  readelf -S -W hi5622v100_wifi.ko                  # section table (all sections start at 0)
  readelf -r -W hi5622v100_wifi.ko                  # relocations (which rodata words are fn ptrs)
  ctypes/struct file reads of the .ko sections      # resolved reloc addends, table rows
  wifi.dis.txt (objdump -dr style)                  # instruction-level anchors quoted below

Anchors (function CAs are section-relative .text addresses; all sections start at 0, so a
symbol must be resolved against its own section from readelf -s before reading bytes):

Relocation cross-check that fixes the row layout: the table relocations that point at .text
land on row_base+8 for rows whose id is at row_base+0, so a row is {u16 id; u16 pad; u32 h4;
u32 h8}; wal_config_process_entry selects h8 when its mode argument is 3 and h4 when it is 4.

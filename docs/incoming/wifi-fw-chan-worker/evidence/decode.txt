    validate(band=body[0], channel=body[2], &index) (CA 0x10172c)
    if status != 0: log, return 0x3e8 (no store)

[3] channel validation CA 0x10172c
    band 0: 14-entry table CA 0x117b48 = channels 1..14
    band 1: 29-entry table CA 0x117ad4 = channels 36..196 (5 GHz)
    on a match: return 0 and *out = the index in that table
    on a miss/invalid band: return 0x3e8 (no *out write)

[4] post-store work (all after the ctx stores; none of it changes the ctx word)
    0x0fdce4: writes the VAP object (+0x1A0 bits 1..7) from the band/field class
    0x0f4fd8(module+0x4AC): per-user bookkeeping path (no RF call)
    0x040684: only when module[4] (create type) == 2, and
              0x0944de(module) == 1  ->  0x101890(band,field,channel)
        0x0944de requires module+0x11 == 1 (band 1) and module+0x440 == 1
        and band_object+0xEC8 == 1 (band object = lookup(ctx[0])+0x4B8)
    0x101890 is the 5 GHz-only RF program: it re-validates via CA 0x10172c,
        selects a per-channel-index parameter block from CA 0x10be68 and
        issues the RF-side work through CA 0x101650/0x101BD8 (return 1)
    0x097008: called when per-link+0x1C8 != 0; applies the channel word
        to the band/link state (both bands)

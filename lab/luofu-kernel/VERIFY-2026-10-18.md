## 5. Five success criteria

**(1) Files present with provenance - PASS.**
All five lanes are on disk with the files and line counts the index claims: clk
1,461+4; pci 1,664+50+131; pinctrl 647+6+94; dts 774+64; fragment-audit 136. Every copied body
either matches its source byte-for-byte (clk, dts, pinctrl, fmc, ofpart) or differs only by a
declared, mechanical delta (pci gate; CRLF; Makefile header lines). Caveat F8: all 14 lane paths
are **untracked** in the `opensource` repo, so "published" currently means "present on disk".

**(2) Values traceable - PASS.**
The literal-set comparison in section 4 shows zero values that exist only in a published copy.
For pci the new gate adds no value. The values that are present are inherited from a committed
blob (pci, pinctrl) or from the build tree (clk, dts, mach, fmc, heads), and the build-tree
hashes are recorded in Appendix A.

**(3) Kernel build - UNVERIFIED.**
No kernel or module build was run. The criterion is **unverifiable without replacing the build
tree** (scope forbids it), and the build tree was observed changing during verification (F7).
`vmlinux` exists (11,195,616 B, 21:16:53) and the six audited `.o` files exist, but they predate
this lane set and are not evidence that the published sources build. The lanes' own build claims
are U1-U3.

**(4) PCIe gate present - PASS (structural).**
`pci/Kconfig` defines `LUOFU_PCIE` and `LUOFU_PCIE_ENABLE_LINK_WRITES`, both `default n`
(lines 13 and 30). The source references the symbol 7 times. Every compiled `writel()` is inside
a gate region: line 557 inside `#if LUOFU_PCIE_LINK_WRITES` (540-559); 751, 819, 820, 885 inside
745-892; 1126 inside `#if LUOFU_RC_WRITE` (1105-1304), where `LUOFU_RC_WRITE` is bound to the
same symbol. `probe()` returns 0 at line 1485 without calling `pci_host_probe()`; the only
`pci_host_probe` text is in a commented scaffold (lines 1501, 1563, 1574, 1578). The
"compiles no `writel()` at all" claim was not executed (U1), but the preprocessor structure is
consistent with it.

**(5) `git status` free of build artifacts - FAIL.**
`git status --porcelain -- lab/luofu-kernel` lists **no** `.o`, `.ko` or `.dtb`, so the literal
status check passes. The tree is nevertheless not artifact-free: **10 ELF `.o` files are tracked
in HEAD** (F1), and 14 tracked files show as modified (CRLF-only) plus 8 untracked lane paths.
If the criterion means "the published tree contains no build artifacts", it fails.

## 6. Findings (disagreements with the lane reports or context)

**F1 - 10 tracked build artifacts.** `git ls-files '*.o' '*.ko' '*.dtb'` in the `opensource`
repo lists ten `.o` files under `lab/luofu-kernel/nand/`, all real ARM ELF relocatable objects
(`file`: `ELF 32-bit LSB relocatable, ARM, EABI5 ... with debug_info, not stripped`):
`nand/parsers/ofpart_triductor.o`; `nand/triductor/tri_fmc.o`, `tri_mtd_parts.o`;
`nand/triductor/nfc_tr6560/{tri_hal_nand,tri_nand,tri_nand_bbt,tri_nand_check,tri_nand_drv_yyxxxx,tri_nand_mtd,tri_spi_nand_drv}.o`.
They are committed, so `git status` will never report them; criterion 5 fails on the tree, not on
the status text.

**F2 - the patch has a fourth edit the README does not mention.** `kernel-tree.patch` contains
four hunks:
`arch/arm/mach-hisi/Kconfig`, `arch/arm/Makefile`, `arch/arm/boot/dts/Makefile`, and
`drivers/mtd/ubi/io.c`. The fourth adds `compat != 5` to `validate_vid_hdr()`, accepting the
vendor flash's layout-volume compat value. `README.md`'s image-lane table calls the patch "3
in-tree edits" and names only the first three. The build tree has all four applied (reverse
dry-run exits 0; `grep` finds `compat != 5` at `drivers/mtd/ubi/io.c:870`, `ARCH_LUOFU` at
`arch/arm/mach-hisi/Kconfig:58`, the machine line at `arch/arm/Makefile:185`, and the dtb line at
`arch/arm/boot/dts/Makefile:243`). This is substantive, not cosmetic: the fourth hunk changes
kernel behaviour on read.

**F3 - the fragment count is 8 absent, not 7, by literal symbol.** `luofu.fragment` requests 13
`CONFIG_*LUOFU*` lines; `.config` has 6 LUOFU symbols. Literal intersection is 5
(`ARCH_LUOFU`, `MTD_NAND_LUOFU`, `LUOFU_GMAC`, `LUOFU_MDIO`, `LUOFU_WATCHDOG`).
`CONFIG_CLK_LUOFU` is absent from `.config` while `CONFIG_LUOFU_CLK=y` is present (line 2942).
So 8 fragment lines have no matching `.config` line, not 7. The audit itself explains the
spelling mismatch; its "exactly 7 ... none of them appears" sentence is wrong unless CLK is
counted as satisfied out of band.

**F4 - C9 is false.** The published `dts/luofu-r116.dts` compiles **as-is** with the exact recipe
in `dts/README.md`; exit 0, six warnings, md5 `7be579be137c2e83868e3dcba32f3956`, identical to
the build tree's DTB. No header stripping is required. The lane's caution is unnecessary.

so compare modulo `\r`" and that the header is a "22-line comment block ending at line 23".

**F7 - the build tree changed during verification (not by this task).**
